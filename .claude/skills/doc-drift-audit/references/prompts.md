# Промпты для субагентов

Каждый промпт — свежему субагенту без контекста сессии. Указать **точный список файлов**, которые ему можно читать, и запретить остальное: иначе невозможно оценить, что он вывел сам, а что подсмотрел. Ответ — дословно в файл отчёта.

Общий хвост для всех: «Only use what the given files support; do not invent typical-project assumptions. If something cannot be derived from the files, write it as an explicit TODO question / mark it *(inferred)*.»

## №1. Поиск расхождений (шаг 2, запускать ≥2 раз)

Вход: старая документация + `facts.md`.

> «Вот текущий README проекта: [README.md]. Вот актуальная структура репозитория: [facts.md]. Найди расхождения между документацией и реальным кодом.»

Формат ответа: таблица `# | Раздел | Что написано | Что в реальности (раздел facts) | Тип (устарело / отсутствует / дублируется / неточно) | Приоритет P1–P3`, затем «Чего не хватает вообще», затем «Не могу проверить по этим данным».

Раздел «Не могу проверить» — индикатор полноты facts: если там конфиги, значит `collect-facts` их не собрал.

## №2. Раздел установки README

Вход: раздел Getting Started, `package.json`, `facts.md`.

> «Вот текущий раздел установки в README: [вставить]. Вот актуальный файл зависимостей и конфигурации: [вставить]. Перепиши раздел так, чтобы шаги точно соответствовали текущему проекту.»

Добавить: сохранить стиль и уровни заголовков README.

## №3. Setup-гайд (docs/ONBOARDING.md)

Вход: README, `facts.md`.

> «На основе структуры проекта [вставить] и текущего README составь пошаговый setup-гайд для нового AQA-инженера, который впервые клонирует репозиторий.»

Добавить: нумерованные шаги от clone до первого прогона, у каждого — точная команда и «you should see …»; неизвестное — TODO-вопросом.

## №4. Архитектура + диаграмма (docs/ARCHITECTURE.md)

Вход: `facts.md` (файлы, конфиги, экспорты). Лучше дать и тела ключевых классов — без них Claude не видит связей (навигация Page Object → Page Object, кто вызывает helpers).

> «Вот список ключевых классов и папок фреймворка: [вставить]. Опиши архитектуру фреймворка простым языком: какие слои есть (page objects, тестовые данные, конфигурация, раннер) и как они взаимодействуют.»
> + «Сгенерируй текстовое описание для архитектурной диаграммы, отражающей текущую структуру» — Mermaid flowchart + абзац текста.

Добавить: «Only layers/classes that exist — no BasePage, API clients, builders, logger unless the facts show them.»

## №5. «Что изменилось» (docs/CHANGELOG.md)

Вход: `git log <base> --date=short --format="--- %h %ad %s%n%b" --stat` (агенту можно разрешить только эту команду).

> «Вот список коммитов за последний месяц: [вставить]. Составь краткое резюме архитектурных изменений для раздела "Что изменилось" в документации.»

Добавить: от новых к старым, для автора тестов (переименования, новые слои, env, способ запуска), догадки по именам файлов — *(inferred)*. Сверка: `git show <commit>:<file>` для каждого *(inferred)* и для env/конфигов — смена смысла переменной в log не видна.
