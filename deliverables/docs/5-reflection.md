**Главный вывод.** Claude силён в сопоставлении двух текстов и не выдумывает, если запретить это явно. Но полнота ответа ограничена тем, что ему дали:

Поэтому полезная работа делится так: Claude готовит черновик и список кандидатов, человек проверяет каждую строку.

## Ошибки, пойманные у себя

- **Collector прятал `package-lock.json`.** Получилась ложная тревога в v1. Без конфигов половина README ушла в «не могу проверить», без workflow не было триггеров CI. Всё это исправлено в скрипте.

- **Мой текст в CHANGELOG** «`ADMIN_*` are new» — неверно. Поймала той же проверкой `git show`, что и ошибки Claude.

- **«Исправление» про EBADENGINE было ошибкой.** 03.11 исходную верную фразу «`npm ci` prints EBADENGINE» я посчитала неточной по документации npm и сузила до зависимостей. 06.11 проверено запуском: npm предупреждает и по корневому `engines`. Урок: поведение инструмента проверять запуском, если это дёшево.

- **Первый прогон шага 8 с `--reporter=list`** не создал отчёт. Это ошибка проверки, а не документа. Урок: прогонять ровно команды из гайда.

Вывод из паттерна «черновик → сверка → именное подтверждение»: сверка нужна **любому** тексту, а не только сгенерированному.

## Скилл `doc-drift-audit`

Оформлен в [.claude/skills/doc-drift-audit/](../../.claude/skills/doc-drift-audit/SKILL.md). Копия синхронизирована в `~/.claude/skills/`.

| Что | Откуда взялось в этом прогоне |
|---|---|
| `collect-facts.mjs`: файлы без фильтров, конфиги и CI-workflow целиком | ложная тревога v1, «не могу проверить», пропущенные триггеры CI |
| `check-doc-refs.mjs`: пакеты, ветки, исторические пути, голые имена файлов, проверка версии Node по engines | 6 ложных срабатываний первой версии + P1 по Node |
| Правило «≥2 независимых прогона, объединять» | v1 и v2 нашли разное |
| Правило «наводки фиксировать как наводки» | находка D2 в v2 |
| Правило «не править входные файлы, пока субагенты читают» | утечка `engines` в черновик раздела установки |
| Правило «смену смысла env проверять через `git show <commit>:<file>`» | пропуск обоих: моего и Claude |

**Как запускать регулярно:**

- Короткий цикл (facts → 2 прогона → `check-doc-refs` → P1/P2) — перед релизом или раз в спринт.

- Полный цикл с ONBOARDING на чистом клоне — после PR, который меняет Node/Playwright/ESLint, env-переменные, `projects` или CI.
