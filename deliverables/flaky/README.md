# Flaky-тесты: анализ и стабилизация STORE-*

Задание 12 «Анализ flaky-тестов» (AQA). Ветка `feature/flaky-store-tests`, набор `tests/store/store.spec.ts`,
полный цикл — по **STORE-02** (сортировка по цене), остальные store-тесты — общий паттерн (шаг 5).
Работа идёт по этапам **Research → Plan → Implement → Verify**; каждому этапу соответствует один файл.

> **Статус:** цикл завершён 2026-11-05 (статика — 2026-11-02, прогоны, фикс и верификация — 2026-11-05,
> `qa-sandbox.inno.ws`). Фикс STORE-02 — в рабочем дереве, не закоммичен.

## Итог

- **Причина STORE-02:** тест читает список **раньше, чем приходит отсортированный ответ**. Клик доходит до
  сервера (запрос `?sortBy=price_desc` есть в 55/55 проверенных падениях), а `allTextContents()` выполняется через
  ~5 мс после отправки запроса, на 50–95 мс раньше ответа. Гипотеза H2 доказана repro: ответ сортировки
  задержан на 3 с → 10/10 fail. Гидрация (H1, версия комментария и `FLAKY-TESTS.md`) не наблюдалась ни разу.
- **Не флейк, а always-fail в обычных условиях:** 0 pass из 90 (base, parallel, isolated, cold). Флейк
  появляется только под CPU ×20: 5 pass из 50. Заявленные в комментарии ~40–60% не подтвердились.
- **Тест или продукт:** **тест**. Продукт сортирует стабильно: 20/20 прямых загрузок дают один порядок
  (H6 опровергнута). Отдельный вопрос к **данным стенда**: все цены €10.00, поэтому «T-Shirt первый» держится на
  tie-break сервера, а не на цене.
- **Фикс:** `sortBy()` в PO ждёт смену URL после клика; в спеке retrying-ассерты `toHaveURL` + `toHaveText` вместо
  однократного чтения, плюс проверка цен по невозрастанию. Без sleep, ретраев и роста таймаутов; ассерт усилен.
- **До → после:** 100% → **0%** падений, по 30 прогонов в base, parallel и cold. Repro H2 и CPU ×20 — 10/10 pass.
  Две негативные проверки падают с понятным сообщением. lint, typecheck и `npm test` зелёные.
- **Остальные STORE:** стабильно проходят в base, parallel и cold (по 20). Это латентные дефекты, общий паттерн —
  [1-research.md §5](1-research.md#5-общий-паттерн-остальные-store-тесты). Условие throttled для их проверки
  оказалось невалидным: под ним не проходит `goto`.

```text
deliverables/flaky/

├── 5-reflection.md    рефлексия + журнал промптов
└── runs/
    ├── stats.md       сводка flaky-stats по всем прогонам (тест × условие, до/после)
    ├── before/        1 файл на прогон: <date>_<condition>[_<block>].json, meta — в ключе _meta
    ├── after/           (+ cpu_pass_vs_fail/run-30x.log в before/)
    ├── trial/         пробное падение: error-context, скриншот
    └── _local/        не коммитится: логи упавших прогонов, trace.zip (в них session link стенда)
```

Инструменты не дублируются здесь: всё переиспользуемое — в скилле
[`flaky-tests`](../../.claude/skills/flaky-tests/SKILL.md) (`.claude/skills/flaky-tests/`), специфика проекта —
в [`.flaky/`](../../.flaky/): [`profile.md`](../../.flaky/profile.md) (команды, параметры, конвенции, что не трогать)
и `apply-repro.patch`, плюс `negative-wrong-order.patch` для негативной проверки «сортировка сломана».

## Инструменты

| Файл | Что делает |
|---|---|
| `$SK/scripts/run-condition.mjs` | Запускает одно условие матрицы, кладёт один файл на прогон в `runs/<phase>/` (meta в ключе `_meta`; лог — только при падении, в `runs/_local/`): коммит, `dirty`, `BASE_URL`, версии, время, снимок каталога |
| `$SK/scripts/flaky-stats.mjs` | Сводит отчёты в таблицу «тест × условие → pass / fail / % по целевой причине / % шума», сравнивает до и после |
| `$SK/scripts/list-snapshot.mjs` | Товары и цены в порядке SSR (селекторы — в профиле); `--repeat K` — меняется ли порядок сортировки между загрузками (гипотеза H3) |
| `$SK/templates/playwright/repro-conditions.ts` + `.flaky/apply-repro.patch` | Включает условие (`REPRO_CONDITION=…`) в фикстуре `page` настоящего теста; патч локальный, не коммитится |
| `$SK/templates/playwright/cold.config.ts` | Условие «cold»: store-тесты без логина админа и warm-сессии; cookie `SESSION_LINK` — через `REPRO_CONDITION=gate` |

`$SK` = `.claude/skills/flaky-tests`.

Команды — в [1-research.md](1-research.md#команды).
